# Full-sequence window/session reuse implementation plan

Status: implementation-ready design spec  
Date: 2026-06-14  
Scope: project repo `nlp_research_project` plus sibling library
`../circuit-tracer_chunked`

## Problem statement

The `fullseq-telemetry-v1` pilot validated that prefix-effective
`full_sequence` traces can exactly reproduce the independent-prefix compact
graphs for selected `94_base` and `828_base` targets, and that decoder/session
reuse is output-equivalent. However, decoder-cache reuse alone gave only modest
or negligible runtime improvement because most runtime remains in repeated
target-local setup, Phase 3, and Phase 4.

For the next productionization step, implement a fixed-configuration
full-sequence window/session mode that reuses all target-independent resources
that are scientifically acceptable under the calibrated soft/core metric regime,
while keeping target-dependent attribution semantics explicit and measurable.

The user requirement is to implement the six currently identified reuse
strategies:

1. model/tokenizer/transcoder session reuse,
2. full-sequence tokenization, hash, prefix metadata reuse,
3. decoder chunk cache reuse,
4. Phase-0 window-state reuse,
5. prefix mask / compact column mapping reuse,
6. target-logit reuse from cached window logits.

Phase-0 reuse and target-logit reuse must be separately toggleable so their
effects can be validated independently.

## Scope

In scope:

- Add an explicit full-sequence window/session reuse mode for contiguous shard
  windows.
- Reuse target-independent setup state inside a shard/window under a single fixed
  run configuration.
- Keep Phase 3 and Phase 4 per target for the first implementation.
- Persist enough telemetry to show where setup savings appear and whether cache
  reuse changes CUDA/host memory pressure.
- Validate against the already completed telemetry pilot configuration so the new
  mode can be compared with:
  - `independent_prefix_per_token`,
  - `full_sequence_per_token`,
  - `full_sequence_experimental_reuse`.

Non-goals for this implementation pass:

- No Phase 3 frontier reuse.
- No Phase 4 row/direct-effect reuse.
- No selected-feature-set reuse as an exact-trace shortcut.
- No default change for large scientific runs until the validation matrix passes.
- No claim that the new mode is bit-identical to the old prefix-effective
  per-token path. The new mode is a fixed full-sequence/window configuration and
  should be evaluated with the calibrated soft/core metrics plus structural
  sanity checks.

## Assumptions

- Heavy model/GPU work remains SLURM-only.
- The sibling library owns attribution/session internals; the project repo owns
  planning, sharding, launch, aggregation, audit, and experiment provenance.
- Floating-point/trace-shape drift is acceptable if all compared runs use the
  same fixed window/session configuration and validation remains within the
  calibrated near/noise controls.
- Exact graph-ID equality to prefix-effective per-token is desirable but not a
  hard promotion gate for Phase-0 window reuse.
- Phase 3/4 remain target-dependent and should be recomputed per target unless a
  later row/direct-effect prototype proves row-level equality.

## Proposed run knobs

Add explicit knobs rather than overloading the current experimental reuse mode:

| Knob | Values | Purpose |
|---|---|---|
| `trajectory_session_mode` | `per_token`, `experimental_reuse`, `window_reuse_v1` | Selects the session implementation. |
| `reuse_phase0_window_state` | bool | If true, build Phase-0 state once at the window max prefix and derive per-target prefix views. |
| `reuse_target_logits` | bool | If true, read target logits from cached window logits instead of per-target logits. |
| `phase0_window_scope` | `shard_window`, `trajectory` | Defines max-prefix state boundary; start with `shard_window`. |
| `phase0_window_max_prefix_policy` | `max_target_position` | Builds state at max target position in the window. |
| `phase0_window_reference_checks` | `off`, `sampled`, `all` | Optional per-target comparison against current per-token setup path for validation. |

Validation matrix toggles:

1. Baseline: `reuse_phase0_window_state=false`, `reuse_target_logits=false`.
2. Logit-only: `reuse_phase0_window_state=false`, `reuse_target_logits=true`.
3. Phase0-only: `reuse_phase0_window_state=true`, `reuse_target_logits=false`.
4. Combined: `reuse_phase0_window_state=true`, `reuse_target_logits=true`.

The implementation should reject `reuse_target_logits=true` unless a compatible
window/session state with cached logits is available.

## Implementation stages

### Stage A — Project harness and schema plumbing

Project repo work:

1. Extend trace-spec/schema validation to recognize the new knobs.
2. Add CLI/planning support for `window_reuse_v1` and the two independent toggles:
   - `reuse_phase0_window_state`,
   - `reuse_target_logits`.
3. Ensure contiguous-window shards record:
   - `window_start_generated_index`,
   - `window_end_generated_index`,
   - `window_max_target_position`,
   - all target positions in the window.
4. In `full_answer/runner.py`, create a trajectory/window session once per
   contiguous window, then process targets inside that session.
5. Persist per-window and per-token metadata:
   - session mode and toggles,
   - max-prefix length,
   - full-token hash,
   - prefix hashes,
   - whether Phase-0 state reuse and target-logit reuse were effective.

Acceptance criteria:

- Login-safe unit tests cover trace-spec validation and shard/window grouping.
- Print/list mode shows session mode and toggles without loading models.
- Existing `per_token` and `experimental_reuse` behavior is unchanged.

### Stage B — Sibling session API skeleton

Sibling library work:

1. Add a small explicit session object, e.g. `FullSequenceWindowAttributionSession`.
2. Session construction owns:
   - model/transcoder references,
   - full token IDs,
   - window max-prefix IDs,
   - decoder cache,
   - optional Phase-0 window state,
   - optional cached logits.
3. Provide a target method that returns the same artifact shape as the current
   per-target attribution call.
4. Keep per-target fallback to the current attribution path.

Acceptance criteria:

- Unit tests can instantiate a fake session with fake tensors and process two
  targets without leaking future positions.
- If all reuse toggles are false, the session path delegates to the current path.

### Stage C — Reuse strategies 1--3: stable session resources

Implement the safe resource reuse layer first:

1. Model/tokenizer/transcoder already stay process-local; make session ownership
   explicit in metadata.
2. Tokenization/hash/prefix metadata:
   - tokenize full sequence once,
   - compute full token hash once,
   - precompute target prefix hashes for all targets in the window.
3. Decoder cache:
   - reuse existing fingerprinted decoder chunk cache across target calls,
   - expose hit/miss/eviction/resident-byte telemetry per token and per session.

Acceptance criteria:

- Per-token vs resource-session-only output remains exact on selected validation
  targets.
- Decoder cache hit/miss telemetry is persisted in trace JSON, not only logs.

### Stage D — Reuse strategy 4: Phase-0 window-state reuse

Implement Phase-0 reuse as a toggleable experimental path.

Sibling design:

1. Factor current setup into two conceptual operations:
   - build immutable `Phase0WindowState` at `window_max_prefix_len`,
   - derive per-target `AttributionContext` / prefix view from that state.
2. `Phase0WindowState` should include, at minimum:
   - max-prefix token IDs,
   - setup diagnostics,
   - activation matrix / active features,
   - reconstruction/components needed by later phases,
   - token vectors,
   - logits for max-prefix positions,
   - hashes/fingerprints for state provenance.
3. Per-target derivation must mask or compact away all state with
   `pos >= target_position` before Phase 3/4 sees it.
4. The derived target context must pass the existing prefix-view audits:
   - no active feature position beyond target prefix,
   - no token/error/nonfeature node beyond prefix,
   - compact bucket widths match prefix-visible length.

Acceptance criteria:

- Same-session repeated target is exact.
- `reuse_phase0_window_state=true`, `reuse_target_logits=false` completes the
  validation matrix and records Phase-0 setup amortization.
- Prefix-view audits pass for all targets.

### Stage E — Reuse strategy 5: prefix masks and compact column mappings

Add precomputed per-target prefix views over the Phase-0 window state:

1. For each target position, precompute masks or index maps for:
   - active features with `pos < target_position`,
   - compact feature columns,
   - token/nonfeature columns,
   - row-store dimensions and node IDs.
2. Store lightweight hashes/counts for each mapping:
   - active feature count,
   - selected prefix-visible feature column count,
   - token/error column counts.
3. Ensure these mappings are used only for shape/layout selection, not as
   selected-feature/frontier reuse.

Acceptance criteria:

- Per-target mapping counts match independently reconstructed prefix views.
- Audits fail closed if any future-position column enters a compact graph.

### Stage F — Reuse strategy 6: target-logit reuse

Implement target-logit reuse separately from Phase-0 state reuse.

Design:

1. If `reuse_target_logits=true`, read the target logit/probability/rank from the
   cached window logits at `output_position = target_position - 1`.
2. If `reuse_target_logits=false`, obtain target logits through the current
   per-target path even if Phase-0 state is reused.
3. Record `target_logit_source` in trace metadata:
   - `per_target_trace`,
   - `window_cached_logits`.
4. Validation should run logit-only and Phase0-only modes independently before
   combined mode.

Acceptance criteria:

- Logit-only mode completes and compares cleanly against baseline.
- Phase0-only mode isolates any differences caused by Phase-0 state reuse.
- Combined mode has no unexplained additional drift beyond the isolated modes.

## Telemetry requirements

Persist the following in machine-readable trace/session JSON, not only stderr:

- Per-session:
  - session mode and toggles,
  - window max-prefix length,
  - session construction seconds,
  - Phase-0 window setup seconds,
  - Phase-0 window active feature count,
  - cached logits shape/dtype/source,
  - decoder cache resident bytes, hit/miss/eviction counts,
  - CUDA peak allocated/reserved during setup,
  - cgroup/RSS/file-cache peaks where available.
- Per-target:
  - whether Phase-0 reuse was requested/effective,
  - whether target-logit reuse was requested/effective,
  - target logit source,
  - prefix-visible active feature count,
  - prefix mapping construction seconds,
  - Phase 3/4 timings,
  - graph save size,
  - CUDA and cgroup peaks attributable to the target if available.

## Validation run plan

Use the same prompt configuration as `fullseq-telemetry-v1` so results compare
directly against existing artifacts.

Fixtures and targets:

- `94_base`: generated indices `0`, `220`; target positions `80`, `300`.
- `828_base`: generated indices `0`, `227`; target positions `73`, `300`.

Reference roots:

- `/fs/scratch/PAS3272/kopanev.1/exact_trace_bench/cardinal/fast/fullseq-telemetry-v1`
- final reference run id: `rerun_prefix-trace-fix2_mem460_fadvise_20260614`

Run matrix under the new session implementation:

| Mode | `reuse_phase0_window_state` | `reuse_target_logits` | Purpose |
|---|---:|---:|---|
| resource-session-only | false | false | Confirms new session wrapper does not change current behavior. |
| logit-only | false | true | Isolates cached target-logit effect. |
| phase0-only | true | false | Isolates Phase-0 window-state reuse effect. |
| combined | true | true | Intended production candidate. |

Comparisons:

1. Same-mode repeat for each new mode: should be exact.
2. Resource-session-only vs existing `full_sequence_experimental_reuse`: should be
   exact or explainable by metadata-only differences.
3. Logit-only vs resource-session-only: target-logit deltas should be tiny and
   recorded.
4. Phase0-only and combined vs resource-session-only:
   - structural compact comparison,
   - frozen primary metric `logit<-error / union_raw_weight_cosine / {}` where
     feasible,
   - secondary top-p core shared-mass metrics,
   - prefix-view audit.

Resource settings for Cardinal validation:

- `--mem=460G`, unless a preflight shows the new mode exceeds this cap.
- `row_store_cache_control=fadvise_dontneed_after_append_v1`.
- typed-bucketed compact saves.
- `exact_trace_internal_dtype=fp32`.

Promotion criteria:

- No prefix-view audit failures.
- Same-mode repeats exact.
- Resource-session-only exact against current reuse reference.
- Combined mode reduces setup/total runtime materially versus current reuse.
- Phase0/logit drift, if present, stays within calibrated near/noise controls and
  is stable under same-configuration repeats.

Stop criteria:

- Any future-position leakage.
- Same-mode non-determinism.
- Target-logit reuse causes unexplained large logit/readout shifts.
- Phase0 reuse introduces drift that exceeds calibrated near-case controls or
  changes conclusions under the frozen metric.

## Risks and open questions

- NNSight trace shape may still change activation membership under Phase-0 window
  reuse. This is acceptable only if fixed-configuration comparisons stay stable
  and calibrated soft/core metrics remain near-case.
- Holding a full Phase-0 window state may increase peak CUDA or host memory. The
  implementation must be able to discard or CPU-stage state before per-target
  Phase 3/4 if needed.
- Full-trajectory scope may be too large for Cardinal memory. Start with
  contiguous `shard_window` scope and promote to trajectory scope only after
  memory telemetry supports it.
- The target-logit toggle may require factoring code that currently obtains logits
  implicitly from the per-target context; keep fallback simple.
- Phase 3/4 remain the likely dominant per-target cost. Do not pursue row/direct
  reuse until this window/session mode is validated and measured.
