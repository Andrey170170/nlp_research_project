# Full-sequence productionization plan

Status: working implementation spec  
Date: 2026-06-13  
Scope: project repo `nlp_research_project` plus sibling library
`../circuit-tracer_chunked`

## Problem statement

Metric calibration selected the next full-answer tracing default as:

- `input_context_mode=full_sequence`,
- unbuffered Phase 3/4 frontier selection by default,
- typed-bucketed compact saves,
- `exact_trace_internal_dtype=fp32`.

The current full-sequence path is validated enough for selected-token
comparisons, but it is not yet production-hardened for large all-token runs. It
still performs one attribution call per target token and discards most
target-independent setup/cache state between calls. Before Phase-3 scale-out, we
need to make full-sequence tracing correct, measurable, and reuse-friendly.

## Scope

In scope:

- Fix full-sequence prefix-view graph metadata invariants.
- Add telemetry and small SLURM pilots to identify actual bottlenecks.
- Make all-token full-sequence planning first-class in the project harness.
- Improve sharding so reuse is possible and stragglers are controlled.
- Define and implement a safe decoder-cache reuse policy.
- Prototype a trajectory-local full-sequence session that reuses immutable setup
  while preserving per-target attribution semantics.

Non-goals for stages 0--3:

- No default Phase 3/4 frontier buffering unless a later unified rerun shows it
  materially narrows the calibrated mid/late noise band.
- No broad Phase 3/4 row/direct-effect reuse yet; that is a later, higher-risk
  prototype after trajectory-local session reuse is validated.
- No scientific correct-vs-wrong claim from this work alone; this is runtime and
  correctness infrastructure.

## Assumptions

- Heavy model/GPU work runs only inside SLURM jobs.
- The sibling library remains the attribution implementation owner.
- The project repo remains the trajectory, sharding, launch, aggregation, audit,
  and experiment-provenance owner.
- The frozen primary calibration metric is
  `logit<-error / union_raw_weight_cosine / {}` for mid/late positions.
- Early generated positions remain reliability-caveated.

## Stage 0 — Correctness hardening and telemetry baseline

### Goal

Make the existing per-token full-sequence path safe and measurable before adding
reuse.

### Work items

1. Fix sibling compact-output prefix-view metadata:
   - In `full_sequence_target_position` mode, compact graph `n_token_nodes` must
     equal the prefix-visible token count, not the full-sequence length.
   - Raw `Graph` output should use prefix-visible `input_tokens` for graph node
     layout; full-sequence tokens may be stored separately as metadata.
2. Add full-sequence prefix-view invariants:
   - `n_token_nodes == prefix_len`,
   - `n_error_nodes == n_layers * prefix_len`,
   - token-edge bucket widths match prefix-visible token count,
   - no active feature, selected feature, row node, error node, or token edge
     references `pos >= target_position`.
3. Add regression tests comparing independent-prefix and full-sequence
   prefix-view traces on selected targets:
   - first generated token,
   - middle generated token,
   - late/final generated token.
4. Add/standardize telemetry in trace outputs:
   - Phase 0/1/2/3/4/5 timings,
   - decoder cache hit/miss/eviction/resident bytes,
   - row-store append/read/materialization timings,
   - CUDA peak allocated/reserved,
   - MaxRSS/cgroup memory when available,
   - graph save size and active/selected feature counts.
5. Run a small SLURM telemetry pilot on canonical fixtures:
   - `828_base`, `361_base`, `94_base`,
   - one early, one mid, one late target where available,
   - full-sequence, unbuffered, typed-bucketed, fp32.

### Acceptance criteria

- Prefix-view metadata and graph-shape invariants pass in unit tests.
- Pilot traces complete with no prefix-view audit failures.
- Telemetry explains enough runtime to identify the dominant bottlenecks.
- Existing selected-token full-sequence artifacts remain interpretable under the
  fixed metadata contract.

### Stop/go

- Go to Stage 1 if all canonical pilot traces complete and telemetry is present.
- Stop if full-sequence and independent-prefix prefix-view comparisons reveal
  future-position leakage or unexplained graph-shape mismatches.

## Stage 1 — Project harness all-token planning and sharding

### Goal

Make all-token full-sequence runs first-class in the project harness and shard
them in a way that supports reuse without unacceptable stragglers.

### Work items

1. Add an explicit all-token selector in
   `src/nlp_research_project/exact_trace_bench/full_answer/selection.py` or the
   CLI layer.
2. Promote `input_context_mode` from an opaque graph knob to a validated planning
   field or consistently validated knob in trace specs.
3. Hoist full-sequence reconstruction in
   `full_answer/runner.py::run_real_shard`:
   - reconstruct full token sequence once per shard/trajectory,
   - compute full-sequence token hash once,
   - reuse it while still creating per-target prefix metadata.
4. Replace or extend `prefix_token_count_lpt_v1` with full-sequence-aware
   sharding:
   - group contiguous generated-token windows,
   - LPT over windows rather than individual scattered positions,
   - record predicted vs actual runtime per window.
5. Add shard health summaries:
   - predicted cost,
   - actual wall time,
   - max token time,
   - CUDA/host memory peak,
   - failed token count,
   - retry recommendation.

### Acceptance criteria

- CLI can generate an all-token full-sequence trace plan without hand-written
  index lists.
- Shards preserve contiguous windows when requested.
- Runner reconstructs full-sequence token IDs once per shard in full-sequence
  mode.
- Print-only and login-safe tests cover all-token selection, trace-spec
  generation, and sharding behavior.

### Expected gain

- Mostly orchestration reliability.
- Expected wall-clock improvement: about `1.1x--1.3x` from less cache churn and
  fewer stragglers, before sibling-level reuse.

### Stop/go

- Go to Stage 2 if pilot shard predicted/actual makespan error is within about
  `25--30%` and no shard exceeds memory limits.
- Stop if contiguous-window packing creates unacceptable load imbalance.

## Stage 2 — Decoder cache reuse policy

### Goal

Turn the existing decoder chunk cache into a deliberate full-answer production
knob and avoid repeated immutable decoder loads across target positions.

### Work items

1. Audit current `DecoderChunkCache` lifecycle in the sibling library:
   - `cross_layer_transcoder.py`,
   - `context_nnsight.py`,
   - `attribute_nnsight.py` cleanup paths.
2. Add an opt-in run/trajectory-scoped decoder cache, keyed by:
   - model/transcoder fingerprint,
   - layer id,
   - chunk id,
   - dtype,
   - device,
   - decoder chunk size,
   - lazy/eager provider mode.
3. Ensure cache invalidation is explicit when any key component changes.
4. Expose/report effective decoder-cache policy in trace metadata and launch
   summaries.
5. Benchmark cache policies on the Stage-0/1 pilot:
   - disabled,
   - current per-context default,
   - trajectory/run-scoped cache with bounded bytes.

### Acceptance criteria

- Reused decoder cache produces identical compact outputs to the no-reuse
  reference at fixed `decoder_chunk_size` and dtype.
- Cache hit/miss/eviction/resident-byte telemetry is present.
- Cache budget can be reduced or disabled without code changes.
- No OOM or material CUDA memory regression in pilot runs.

### Expected gain

- Expected wall-clock improvement: about `1.05x--1.25x` if decoder loading/churn
  is material.
- If gain is below `5%`, keep the policy simple and do not over-engineer.

### Stop/go

- Go to Stage 3 if cache reuse gives measurable gain or clearly reduces I/O/cache
  churn without output drift.
- Stop if cache pressure increases OOM risk or changes compact graph outputs.

## Stage 3 — Trajectory-local full-sequence attribution session

### Goal

Stop recomputing target-independent full-sequence setup for every generated
target token while preserving exact per-target attribution semantics.

### Proposed design

Add a library-level or runner-level trajectory attribution session:

1. Load model and CLTs once per shard/window.
2. Run full-sequence setup once per contiguous token window or trajectory.
3. Materialize reusable immutable state:
   - full token IDs and hashes,
   - prefix hashes,
   - full-sequence logits or selected target logits,
   - Phase-0 activation matrix,
   - error vectors,
   - token vectors,
   - chunked decoder state,
   - decoder chunk cache,
   - optional encoder residency state.
4. For each target position:
   - apply prefix-view mask/truncation,
   - validate no future-position references remain,
   - select target logit at `output_position = target_position - 1`,
   - run target-dependent Phase 3/4 attribution,
   - package typed-bucketed compact graph.

### Correctness constraints

- Session reuse must be opt-in until validated.
- Reference selected tokens must compare against the existing per-token path.
- Required equality/tolerance checks:
  - prefix metadata hashes equal,
  - target logits equal within strict tolerance,
  - active feature membership hash equal after prefix masking,
  - selected feature set equal, or any difference explicitly explained by known
    tie instability,
  - compact typed-bucketed graph equal, or primary metric delta effectively zero
    and below calibrated noise tolerance.

### Acceptance criteria

- A trajectory-local session can process a small contiguous window end-to-end.
- Reference tokens match the no-session per-token path under the checks above.
- Telemetry shows reduced setup time per token.
- Failure mode is safe: session path can fall back to per-token attribution.

### Expected gain

- Expected wall-clock improvement: about `1.2x--2.0x`, depending on how much of
  runtime is Phase 0/1/setup versus target-dependent Phase 3/4.

### Stop/go

- Go to unified Stage-D confirmation if session reuse is exact enough and gives
  meaningful speedup on canonical pilot windows.
- Stop if NNSight trace/batch sensitivity causes reused-session outputs to drift
  beyond calibrated near-case noise controls.

---

## Deferred Stage 4 — Row/direct-effect reuse prototype

This is intentionally out of scope for the first productionization pass.

Potential upside is high, but correctness risk and cache-key complexity are also
high. Only revisit after Stage 3 succeeds. Any row reuse must prove row-level
equality against no-cache references, stable frontier membership, bounded storage,
and useful hit rates before becoming a default.

## Production scale-out gate after Stage 3

Before large Phase-3 trajectory scale-out:

- Stage 0 invariants pass.
- Stage 1 all-token/window sharding is available and tested.
- Stage 2 decoder-cache policy is measured and documented.
- Stage 3 session reuse either passes and is enabled, or fails safely and the
  per-token path has a known throughput estimate.
- A unified Stage-D confirmation run validates the locked defaults against the
  frozen primary metric.
- Every serious launch records project and sibling SHAs, dirty files, immutable
  snapshots, trace-spec hash, shard-manifest hash, decoder-cache policy, and
  metric calibration version.
