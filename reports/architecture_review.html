Architecture review: deepening opportunities

Scope: sibling circuit_tracer first, exact-trace harness second. This report uses module/interface/depth/seam/adapter/ leverage/locality/deletion-test vocabulary and avoids detailed new interfaces.

Top recommendation

Start by deepening circuit_tracer/attribution/attribute_nnsight.py. It is the main shallow module: one mega-file owns attribution orchestration, phase policies, row-store behavior, replay validation, prefix views, telemetry, debug bundles, and full-sequence session reuse. Cleaning this seam gives the highest locality and leverage for later harness cleanup.

1. NNSight attribution module split

Strong

Files: attribute_nnsight.py, context_nnsight.py, phase/replay/prefix tests.

Problem

One shallow module mixes orchestration, policy, storage, replay, diagnostics, and session reuse. The public call surface has dozens of knobs.

Deepening direction

Keep the existing entrypoint as a compatibility facade while coherent phase/runtime concepts move behind deeper modules.

flowchart LR subgraph Before A[attribute_nnsight.py mega-module] --> B[phase policy] A --> C[row-store] A --> D[replay bundles] A --> E[prefix view] A --> F[telemetry] A --> G[session reuse] end subgraph After H[compat attribution entrypoint] --> I[deep phase modules] H --> J[deep runtime/storage modules] H --> K[deep validation/metadata modules] end

Deletion test: strong. Extracted helper groups already behave like modules; deleting them from the mega-file should concentrate complexity.

2. Exact-trace policy/config seam

Strong

Files: attribute.py, attribute_nnsight.py, harness runner and knob taxonomy.

The flat attribution interface exposes scheduler, row-store, dtype, cache, replay, and debug policies together. The harness mirrors this wide surface and forwards many details manually.

flowchart TD Before[Wide flat kwargs] --> S[Scheduler knobs] Before --> R[Row-store knobs] Before --> D[Dtype knobs] Before --> P[Replay/debug knobs] Before --> C[Cache/session knobs] After[Compatibility adapter] --> Deep[Deeper policy modules] Deep --> Harness[Harness maps experiments to stable seam]

Benefits: better locality for policy changes and higher leverage for harness integration. Deletion test: strong.
